# 对话中的主动建议与执行

桌宠可以结合用户当前遇到的问题提出一个具体、可实施的建议，例如检查编译错误、编写脚本、执行命令或设置提醒。用户明确同意后，模型使用已有工具执行；复杂编码任务可委派给工作智能体。执行结果必须以工具返回为依据。

## 实现

- `framework/initiative.en.md` 同时接入 provider instructions 和普通 prompt 框架。聊天风格允许情境相关的建议，不要求每轮给建议。
- 常见短回复的工具召回结合紧邻的上一轮用户消息与助手回复，限制长度，额外嵌入在阻塞线程执行。原始输入、情绪和意图分类不变，历史不作为权限授权。新话题、跨角色消息、主动问候不走这条路径；嵌入失败回退原召回。
- `run_command` 纳入动手前确认名单，复用已有命令预览与执行循环。
- 沙箱要求确认且调用方未提供确认回调时，也走现有确认弹窗，避免写文件等操作直接卡在 `SandboxConfirmationRequired`。同一次操作已在沙箱阶段确认且验证后参数未变时，不重复询问；权限拒绝仍优先执行。
- `AllowOnce` 仅放行当前调用；`AllowAlways` 才能记录会话授权。确认注册表保存真实请求 ID，保证轮询端能正确批准或拒绝。

## 手动验收

1. 对桌宠说“每次都得手动检查这个项目的编译错误，挺麻烦的”，观察是否提出贴合情境的具体建议（模型输出不保证每次都提建议）。
2. 对明确的执行建议回复“好，执行吧”，观察是否找到相应工具并推进任务。执行命令时审核实际命令后点击“仅本次允许”。
3. 再请求另一条命令，确认未因上一次单次授权而自动执行。
4. 拒绝建议或确认弹窗，观察是否停止该动作；未操作弹窗时，不应报告已执行。
5. 禁用相关工具或使用只读访问级别，确认已有权限限制仍生效。

这次改动增强已有 LLM 对话和工具链，不新增定时主动打扰，也不增加建议专用前端卡片。真实对话的建议质量仍需配置模型后进行上述验收。
