# Vivian 扩展开发与安装

设置 → 外部连接管理 MCP；设置 → 插件管理完整能力包。MCP 工具和插件工具会进入陪伴侧工具发现，以及工作侧 standard、code、minimal 模式。工作侧每轮刷新工具清单；在工具设置里禁用的能力不会重新暴露。

## MCP 连接

支持本地 stdio 和 Streamable HTTP（JSON 或 SSE 响应）。HTTP 认证可配置请求头，例如 `Authorization=Bearer …`；当前没有交互式 OAuth 登录流程，也不实现旧版 HTTP+SSE 双端点传输、resources/prompts 等协议能力。

本地连接需要启动命令，支持工作目录与环境变量。启动参数推荐使用 JSON 字符串数组，避免 Windows 路径的引号与反斜杠歧义：

```json
["-y", "your-mcp-package", "G:\\My Files"]
```

环境变量与 HTTP 请求头可填 JSON 对象或每行 `KEY=VALUE`。这些值保存在本机 MCP 配置文件中；敏感配置查询和连接管理只接受设置窗口调用。

插件提供的连接也可编辑，用户设置独立保留，重载、更新或重启不会覆盖凭据和启停选择。“恢复插件默认”撤销该连接的用户覆盖并重载来源插件；彻底移除这类连接请禁用或删除对应插件。

“测试连接”会真实启动进程或初始化远程会话，发现工具后关闭，不保存配置或注册长期工具。“保存”保留配置，包括禁用或连接失败的条目。页面显示具体错误、工具清单、重试次数，支持编辑、停用和手动重连。后台按指数退避重试，连续五次重连失败后停止自动重试，手动重连会重新开始。

工具输入保留 `inputSchema` 的必填字段；工具分页完整读取。`isError: true` 会作为执行失败返回，业务失败不会被当作连接掉线；文本、图片、资源块及 `structuredContent` 保留在工具结果中。多模态块的可视化取决于消费端，不代表所有模型均能直接理解所有内容类型。

## 插件包

通过插件页选择 ZIP 或目录，预览名称、版本、依赖、脚本、MCP 声明后安装。ZIP 根目录或唯一子目录必须有 `plugin.json`。导入不会执行插件；新包或内容变更的包需要再次信任。更新复核源文件和当前安装版本的指纹，避免预览后内容变化。安装替换失败时尝试恢复旧文件；极端文件锁冲突下保留恢复目录并返回路径。

包内不允许符号链接、越界路径、Windows 设备文件名或重复文件；最多 10,000 个条目、512 MiB 解压内容。公寓仍使用它的独立安装流程，通用导入不能覆盖内置插件。

```json
{
  "api": 1,
  "name": "my-extension",
  "version": "1.0.0",
  "description": "我的扩展",
  "skills": ["skills/*.md"],
  "tools": ["tools/*.json"],
  "js": ["js/*.js"],
  "protocols": "protocols/**/*.json",
  "mcp_servers": [],
  "requirements": {
    "commands": ["node"],
    "plugins": {"another-extension": "1.0.0"}
  }
}
```

`requirements.commands` 检查 PATH 中的命令或包内相对路径；`requirements.plugins` 使用插件目录名与最低数字版本号。依赖按拓扑顺序加载，循环依赖或未成功加载的依赖会阻止下游插件执行。缺少依赖仍可安装，补齐后重载即可。

禁用、卸载或删除插件会同时撤销依赖它的插件贡献，包括文件协议与 JS 运行时。依赖恢复后，因依赖暂停的插件会自动恢复；用户主动卸载的插件需手动重载或重启。禁用状态独立保存，重新启动也有效。

`protocols` 可声明单文件、目录或 glob；省略时递归读取 `protocols/`。指纹和实际加载使用相同的文件清单。协议只在插件成功加载时提交，编辑后需要重新信任并重载。新内容先完成脚本审计、协议编译和 JS 校验，失败会保留旧运行时；MCP 连接替换失败会尝试恢复旧连接，恢复异常会显示在错误与诊断中。

状态区分已安装未装载、等待信任、缺少依赖、部分可用、已装载和已禁用。附带技能是按需读取的使用指导，不会独立执行操作或获得额外权限。

## 能力发现与自建插件

设置 → 插件的“能力发现与插件建议”保存各角色的能力缺口与候选，支持手动记录、搜索、检查 GitHub 仓库或本地 ZIP/目录、交给工作侧设计，以及忽略建议。工作侧可通过 `plugin_advisor` 使用同一流程；`tool_search` 仍只发现已注册工具。

同一能力在两个独立工作会话中出现缺口后，后台可以查找公开 GitHub 仓库；全局每天最多一次，同一缺口至少隔七天再查，没有新建议时不会反复提醒。自动发现可在此页关闭，搜索使用现有联网配置与额度，不上传原始对话、错误正文或凭据。没有合适候选时可建议设计自建插件，不把搜索失败解释成插件可用。

远程候选必须在仓库根目录明确声明 Vivian `api: 1` 和贡献点；固定到提交版本后才下载包。文件检查只读取声明与代码，不执行 JS、脚本或 MCP，显示依赖及完整待审内容。该入口目前支持公开 GitHub 仓库；其他发布源可先下载到本地再检查，DSH/npm 包不能直接视为 Vivian 插件。

`create_plugin` 和 `install_plugin` 每次均需具体内容的确认，FullControl、会话放行和之前的沙箱许可都不能替代该预览。`install_plugin` 会安装并信任审核过的内容；审核后包或已安装版本发生变化会阻止提交。缺少依赖不会自动安装依赖。原有“导入 ZIP/目录”仍保留安装与信任分开的操作。

设计任务在独立的用户数据工作区准备代码，通过 `create_plugin` 提交，当前工作会话可继续使用新能力。状态区分包检查、安装、装载失败、已装载和成功工具调用；只有对应插件、对应装载指纹的真实成功调用才记录业务验证，装载成功不代表业务已验证。被忽略的建议不会因重启或再次搜索而重新推荐。

运行 `npm run test:plugin-advisor` 验证建议交互、确认边界和本地插件的检查—装载—调用回执；测试不联网搜索或调用真实模型。

## 模型预设更新

设置 → LLM 的“模型预设更新”支持一键核对 `llm-providers` 的全部厂商，也可选择单个厂商更新。使用已保存的工作模型和联网工具，会消耗模型调用额度。页面显示逐厂商进度、模型增减、失败原因、核对日期和官方来源；成功后自动刷新模型候选列表，当前模型选择与密钥保持不变。

每个厂商使用独立核对会话，只能提交该厂商的 LLM 预设。来源必须是在该会话中实际读取成功的 HTTPS 官方资料；证据不足不算成功，并发修改会阻止覆盖。停止操作会等待当前厂商完成后跳过其余厂商。关闭设置窗口不会停止后台核对，重新打开可继续查看；应用重启后未完成项标记为停止，需手动重试。

运行 `npm run test:provider-presets` 验证设置页交互、来源核验和预设写入；测试不调用真实模型。

## JavaScript 宿主

每个插件有独立 Boa 运行时。`ctx.apiVersion` 为宿主 API 版本；`ctx.tool`、`ctx.skill`、`ctx.mcp`、`ctx.provider`、`ctx.on`、`ctx.log` 是注册面。它不是 Node.js 环境，没有 `require`、文件系统或 `fetch` 接口。外部 I/O 应注册 MCP 或声明式 PowerShell 工具。工具处理函数必须同步返回 JSON 可序列化值；返回 Promise 会明确报错。

```js
if (ctx.apiVersion !== 1) throw Error('Unsupported plugin API');
ctx.tool('normalize_label', '整理标签文本', {
  type: 'object',
  properties: { text: { type: 'string' } },
  required: ['text']
}, function (args) {
  return { text: args.text.trim().replace(/\s+/g, ' ') };
});
```

运行 `npm run test:extensions` 验证协议、回执、恢复、工作侧工具发现和插件生命周期。Rust 测试使用独立用户数据目录。
