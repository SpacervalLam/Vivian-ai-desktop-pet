# 桌宠对话自然度与运行时性能审阅

日期：2026-09-30。范围：普通聊天、主动消息、实时语音、人格渲染、认知节拍、图片缓存、3D 房间逻辑、窗口生命周期和模型路由。这是跨模块链路审阅，不是逐行覆盖所有源文件。

工作区原有日记、情绪分类、模型提供者、配置界面等未提交修改；审阅期间动作配置和两个图集也出现其他修改。本次保留它们，没有把它们计入自己的优化成果。没有调用用户的收费模型 API，没有替换模型或调整用户配置。

## 判断

AI 感不能全归因于模型。当前系统把“人格表现、心理状态、感知、任务、输出协议”大量堆在同一轮里，而且不同入口使用不同提示词。模型容易学到“演一个角色”的表面信号，遗漏正在聊的具体事情。增加口头禅、重复要求自然、提高温度，未必改善这个问题。

代码本来已有静默协议、未回应退避、近期自我发言提醒、按关系阶段裁剪人格、请求级采样参数、窗口冻结和按需系统进程采集。这些有用机制应保留；没有必要重新堆一套“真人模拟”规则。

## 已落实改动的测量

### 图集

按磁盘图片宽 × 高 × 4 计算 RGBA 字节数，不用压缩后的 WebP 文件大小代替解码内存。复测 14 张／角色合计 166 MiB，最大的两张合计 40 MiB。新加载器在创建时请求 0 张动作图集；成功缓存强引用最多 2 张。主状态图集、同时进行中的加载、浏览器自有解码缓存和 GPU 纹理不计入这个 40 MiB。

因此能确认的是消除了启动时全量动作预取和长期强持有，不能宣称整个进程立刻减少 126 MiB。浏览器可能继续缓存使用过的图片；真实进程内存需要在相同窗口和相同动作序列下复测。

### 逻辑与 CPU

`tests/runtime-budget.test.mjs` 的 60 秒模拟：

| 渲染频率 | 原逻辑步数 | 新逻辑步数 |
| --- | ---: | ---: |
| 30Hz | 1,800 | 1,200 |
| 60Hz | 3,600 | 1,200 |
| 120Hz | 7,200 | 1,200 |
| 144Hz | 8,640 | 1,200 |

`tests/room-logic-benchmark.ts` 用真实 PetAgent、固定随机种子和初始状态，模拟 180 秒，两个路径均预热，交替测量 7 次，包含新插值的计算成本。自主活动场景中位耗时：60Hz 1054.00 → 107.24 ms；144Hz 1232.36 → 110.92 ms。该数据只覆盖离线角色逻辑，不含 WebView、Three.js 绘制、阴影、后处理及整机 CPU 百分比。固定步长也改变路径决策发生的时刻，两个路径不是逐事件完全相同的工作负载，因此不把约 90% 的微基准改善宣传成应用 CPU 降低 90%。

静止场景非常轻：60Hz 中位 0.94 → 1.12 ms／180 秒，处于这轮样本的波动范围；144Hz 2.17 → 1.54 ms。此次保留固定步长是因为自主活动改善明确且修正了预期 20Hz 的实现；没有声称闲置 CPU 普遍改善。显示插值增加至多一个逻辑步长约 50 ms 的显示延迟，真实窗口中的运动观感仍需人工观察。

首次基准没有重置 PetAgent 静态热点占用表，结果波动明显，已废弃。脚本现每轮 resetClaims 与 bindWorld(null)。额外尝试用“所有任意活动都必须维持硬分离距离”作为断言，但原分离器明确允许贴墙挤压、排除落座，故该断言不能作为此优化的正确性门槛；使用现有路径与对头相遇验收，全部通过。没有为通过检查修改分离器或现有验收标准。

### 提示词

共享 human_feel 文件 UTF-8 体积 7030 → 2439 字节，减少 65.3%。这是该文件的体积，不是完整提示词减少 65.3%，也不是 tokenizer 的精确 token 数。其他人格和动态段落仍较多，需要继续按真实渲染请求测量。

## 第二轮：上下文结构、语音与检索

普通聊天和主动消息共用 `pipeline/message_context.rs`。历史仍以真实 user／assistant 消息传入，已有发言者标记保留；主动触发明确标为“不是新的用户请求”。输出协议位于 system，事件和观察留在尾部。普通聊天不再复制一份完整 system_prompt 后再拆分，而是借用字符串切片，直到创建 API 消息时才复制所需段落。

原拆分器会在动态段中寻找第一个“用户输入”标题，可能把记忆里引用该标题之后的内容误删。新拆分器只移除与本轮输入精确匹配的末尾段，覆盖中、英、日以及输入尾随空白；缺失结构标记时仍保守回退。测试还通过真实 PromptBuilder 验证输入不会再进入动态便签。

实时语音默认摘要分别保留 Vivian 的直接、活泼、轻微嘴硬与 Nana 的从容、温和、有判断力；不再把聊天口头禅、固定频率、拒绝讲解、否认 AI、被忽略后闹情绪等要求带进通话。身份／性格／语气的用户自定义文本保留原文。默认摘要会随角色文件变化而需要维护，不能声称运行时自动总结所有新的人格规则。

本地 payload 实测 UTF-8 文本体积：Vivian SC manifest 9,819 → 1,599 字节（减少 83.7%）；O 的 system_role＋speaking_style 1,661 → 1,597 字节（减少 3.9%，不含 bot_name）。Nana 新 SC manifest 1,662 字节；旧代码没有独立 Nana 人设，因此不作同角色降幅比较。测试约束两位角色的默认 SC 摘要小于 2,500 字节，自定义覆盖不受该预算截断。体积不是精确 token 数，也不是进程内存测量。

SC 使用 `character_manifest`，O 使用 `bot_name/system_role/speaking_style`，沿用原模型字段分支。字段差异参考[火山引擎实时语音官方接入文档](https://docs.volcengine.com/docs/real_time_communication/Accessend-to-endreal-timespeechlargemodel?lang=zh)。本轮只做本地 payload 兼容性测试，没有连接收费语音服务；声音 speaker 仍由已有实时语音配置选择。

语音会话 ID 优先读取当前角色文件，旧全局配置／文件仅供 Vivian 迁移。新文件名由角色 ID 的摘要组成，避免角色 ID 被当作路径。正常停止和 WebSocket 结束都保存对应角色的 ID；不再在停止 Nana 时改写全局 Vivian 会话配置。

主动召回使用音乐、屏幕、应用使用等本次事件与最近用户发言，各取至多 240 字符；不以 assistant 自己的发言当作用户兴趣。即时调侃回应、系统压力、任务报告已有权威材料，跳过该次 Hybrid 搜索；没有事件和用户话题时也跳过。每次命中这些条件可避免一次原本请求 24 条结果的检索；是否涉及远程 embedding 及实际耗时取决于配置，未据此估算整机 CPU 或网络费用。其他触发保留原召回数量和去重流程。

## 模型能力还有哪些可优化空间

1. **先做同模型的上下文减负。** 保留身份、边界、当前话题和少量相关事实；按入口提供适量规则与示例。少而匹配的示例通常比长禁令清单更容易表达期望风格。参考 [Anthropic 的上下文工程说明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)。这是一条设计依据，不是本项目已运行的自然度结果。
2. **把闲聊和执行任务分开评测／路由。** 现有 ModelRouter 支持任务路由，不必让同一个模型同时最擅长陪伴、工具和编程。用实际候选模型在自己的中文多轮案例上盲评，不按通用推理榜单判断陪伴质量。不在此替用户更换模型或增加 API 成本。
3. **采样参数只能辅助。** 配置已有 temperature 0.70、presence penalty 0.3、frequency penalty 0.2 默认值；它们不是本次读到的用户实际配置。代码已按任务和 provider 支持范围应用惩罚。提高温度不能修复错误上下文，频率惩罚也不能识别“换词但同一个话题”的复读。
4. **支持自定义权重或微调时，可以训练风格。** 积累“相同上下文下自然回复／客服式回复”的偏好对，或人工认可的多轮示例，评测后再考虑 SFT／DPO。DPO 的确适用于语气和风格等主观偏好；但要确认所用平台和模型当前支持，训练与维护成本另算。参考 [Microsoft 的 DPO 官方说明](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/fine-tuning-direct-preference-optimization)。
5. **不要默认加第二个 LLM 改写每一句。** 这增加延迟、成本，也可能篡改事实、工具结果和角色边界。优先改源提示词与取材；只有对照评测证明值得时，才考虑受约束的改写。

## 验证与仍需实测的部分

通过：`npx tsc --noEmit`、`npm run build`（含公寓插件检查）、`cargo check --lib --offline`、`cargo test --lib bundle_reader::tests --offline`（3 项）、`node tests/runtime-budget.test.mjs`、`node tests/chat-message-routing.test.mjs`、`npm run check:agent-track`、`git diff --check`。Rust 有仓库现存 unused／dead-code 警告。构建与离线测试不能证明模型自然度或 WebView 实际驻留内存。

第二轮检查通过：共用上下文 4 项、主动行为 3 项、主动渠道／召回 2 项、语音人设与会话迁移 3 项、生成与解析 29 项、PromptBuilder 20 项，另复测资源缓存 3 项，共 64 项；图片加载／固定步长与聊天路由的 Node 回归也通过。扩展回归首次遇到一项旧测试仍要求主调用提取 sleep／expression／importance／long_term_memory，然而 HEAD 中的 JsonProcessor 和提取函数已把这些交给反思阶段；本轮没有改解析器行为。已将该测试修正为验证旧字段不会覆盖反思所属状态，并同步过时注释。

建议模型 A/B 使用相同模型、参数、历史与模拟工具结果，至少覆盖：日常报喜、抱怨、明确求助、用户拒绝调侃、话题结束后的“嗯”、重复整点、未回应后的新事件、无具体感知数据、角色切换、实时语音求助。每案例至少各 3 次。人工盲评具体接话、套话、无必要追问、重复话题；格式错误、编造事实、忽略明确求助直接判失败。原有 `src-tauri/prompts/PROMPT_EVALUATION.md` 可以继续作为基础。

整机性能应分别记录 release 模式单宠闲置、双宠闲置、对话／TTS、打开房间、隐藏房间、观察器开启与关闭，以及反复打开关闭窗口后的工作集／私有提交内存。采样进程必须按父子进程归属识别 WebView2，不能把其他程序的 WebView2 全部加到 Vivian 上。审阅时未发现正在运行的 vivian 进程，因此本次未取得可比的真实应用前后 CPU／RSS 基线。
