# 陪伴侧工具能力与工作侧对齐

两侧已经共用 `execute_tool_use`，包括沙箱、权限、确认、参数规范化、校验、超时、缓存和可观测性。本次优化集中于陪伴侧较早的编排及共享读取能力，继续使用独立工具执行上下文。

| 缺口 | 调整 |
| --- | --- |
| 原生并行结果使用生成的 ID，无法准确匹配模型调用；任务异常可能丢失回执 | 并行结果保持原始 ID 和顺序；异常转成明确失败，执行观测也能结束 |
| 原生调用不替换依赖；文本调用可能在上一批完成前替换 | 两种路径先等待依赖，失败或不存在的依赖生成 UnresolvedDependency，不执行下一步 |
| 两种路径的权限状态、只读上下文修改处理不一致 | 共用并行批次和回执构造；更新上下文后供后续步骤使用；未获得权限时私有执行循环收尾 |
| 只读调用一次全部展开，原生路径启动独立任务 | 最多八个同时执行，结果按调用顺序返回，不留下独立读取任务 |
| 旧非阻塞名单会把不存在的 set_timer 报成已启动 | 等待真实工具回执；调度本身的登记回执不等于后台任务已经完成 |
| 文件请求较小 max_chars 时被扩大到至少 20000；截断后没有续读位置 | 支持字符 offset、next_offset、returned_chars；尊重小预算；默认页同时适配结果预算与上下文裁剪阈值 |
| 大结果提示使用 read_spilled_result，但没有此工具；保存失败仍提示已保存 | 注册分页续读工具，输出 spill_id；完整写入失败不声称可恢复；结果文件使用唯一名称 |
| 整段 JSON 回执会被头尾切割，丢失中间步骤状态 | 针对执行回执保留全部 ID、状态、错误和停止原因，仅压缩证据并标明 evidence_truncated |

`read_spilled_result` 仅接受回执中的文件名，解析后的目标必须是宿主 spill 目录的直接文件，拒绝路径穿越及目录外链接。共享读取工具也向工作侧开放。原有授权工作区边界、工具禁用与工具风险等级继续生效。

文件分页仍按现有编码检测逻辑解码整个文件，再选取字符页；本次没有增加超大文件的流式解码。正文较长时应根据 next_offset 续读，不能把截断预览当成全文。保存结果沿用原有三天临时保留策略。

## 验证

工具测试覆盖并发上限、原始 ID 与顺序、异常及权限失败回执、两种协议依赖和上下文一致性、失败依赖不执行后续步骤、小预算及 Unicode 无损续页、宿主结果通过实际执行器恢复、结果路径限制、转义正文预算裁剪、文件名唯一性。另验证回执 JSON 压缩和本地模拟模型的完整角色隔离流程。

- 工具模块 125 项测试通过。
- 上下文压缩 19 项测试通过，工具执行隔离 4 项测试通过，包括本地模拟模型服务的完整流程。
- 扩展流水线检查：183 项通过、8 项失败、2 项忽略。失败涉及本次未修改的以下模块；本次没有更改它们，也没有把扩展检查报告为全部通过：
  - `compaction_reminder::extract_last_user_topic_truncates_long`：字节数与字符截断期望。
  - `inline_tag_scanner::test_less_than_not_tag`：中文字符边界切片 panic。
  - `injection_guard::detects_chinese_ignore_previous`：中文注入模式未命中。
  - `parsers` 的 JSON processor、状态字段、异步状态解析和流式输出共四项期望不符。
  - `validation::normalize_whitespace_collapses_blanks`：空行折叠期望不符。

这里的扩展失败只确认了当前工作区表现及对应源文件未被本次修改，未通过回退整个工作区构建来判定其引入时间。实际运行版本仍需重新编译启动，真实远程模型措辞未在这些模拟测试中验证。
