# 运行资源与人设自主迭代（2026-10-01）

## 落实的改动

- `get_system_info` 复用 CPU/RAM 采样器，窗口间共享一秒快照；不枚举进程。CPU 采样历史保留到下次查询，首次采样可能为 0，后续查询才有时间差。进程管理仍走自己的查询路径。
- 注意力异步反思在复制文本、创建任务之前取得按角色独立的调用许可。同一角色只允许一个在途请求，失败、超时和取消会释放许可，但仍消耗本次轮数额度与冷却时间。
- 后台分析只读取最近四条普通对话文本；不复制整段历史、工具结果、图片或 reasoning。上一条回复最多 600 字符，用户输入最多 1200，输出预算 256 token。
- 表情／心理／成长反思共用独立的精简 system 协议，不重复发送主对话里的工具说明、检索与附件内容。保留回复前心情、最近对话、角色视角、已知目标、成长候选和可用动作。长输入与长回复保留首尾，明确标记中段省略；用户看到的正文不变。输出预算 1536 token，模型支持时关闭这类结构化分析的额外推理。
- 注意力反思单独以 `attention_reflection` 归属 usage；原有结构化反思仍归属 `reflection`，路由不变。

## 人设如何自主改写

角色通过已有反思调用提出新的局部人设文本，作用域为安慰、关心、赞美、幽默、闲聊、分歧，不增加专门的进化请求。反思中提供当前角色的身份、性格、说话视角和已生效理解，鼓励根据自己的观察与选择改进表达，而不是复制用户的偏好。

过去候选只有文字完全相同才能累计支持。现在每份候选快照提供 `reference`：模型可用 `revises` 引用同作用域、同类型的候选，精炼其文字并继承原证据。引用过期、跨作用域、跨类型或重复来源都会被拒绝。方向改变或反例应提出新候选，不继承旧证据；已生效内容也通过新候选修订。

普通成长仍需跨日独立证据，并沿用六小时晋升间隔；明确、持久的用户纠正可以立即替换对应场景。生效文字进入 `LEARNED_SELF`，替代对应出厂场景与示例，既有渲染缓存随版本自动失效。原始身份和用户手动设置保留。旧生效版本保存在 history，已有成长面板与恢复出厂命令继续可用。删除／修改来源记忆会撤回依赖它的修订。

## 受控测量与取舍

基线 Git 版本：`c01fe000ce975a20e00f1dc7414024cb49892236`。Windows 本地开发构建、未优化 Rust test profile；同一进程内运行新旧路径，计时基准三次运行，每次三组采样。所有保留的性能改动都有下列可复现收益，未保留无收益的额外缓存或渲染改动。

| 实验 | 基线 → 改后 | 结论 |
| --- | --- | --- |
| CPU/RAM 查询，系统 API 已预热，重新创建采样器 | 26.1–29.5 ms → 0.658–0.766 ms；一秒内快照命中约 1–2 μs | 保留；原查询每次枚举 367–371 个进程，新路径为 0 |
| 后台反思历史快照，50 条消息、每条 8000 个汉字，100 次循环／组 | 每次 280–499 μs → 23–26 μs | 保留；同时在节流拒绝时完全跳过快照与任务创建 |
| 同一快照的 UTF-8 文本复制量 | 原历史＋上轮回复至少 1,224,000 字节 → 新回复＋上下文 3,023 字节 | 保留；此项不计元数据、图片或分配器开销，不是整应用 RSS |
| 反思协议，cl100k tokenizer | 4242 → 1264 token（减少 70.2%） | 保留；同时保留表情、心理、目标、长期记忆与成长字段 |
| Vivian 完整出厂人设＋固定短对话的反思样例 | 9579 → 2711 token（包含改后角色视角，减少 71.7%） | 保留；未包含召回、工具协议与成长数据，实际请求随输入变化 |

旧查询第一次运行还会耗费约 321–375 ms，这个初始化值不混入预热后的比较。Token 测量统计消息正文，不计 API 消息封装，不等于所有模型的 tokenizer 或最终账单。旧路径复用主对话缓存前缀，新路径使用稳定的独立协议，缓存折扣取决于供应商。

这里没有启动完整桌宠进行长时间 RSS／CPU 百分比采样，也没有调用付费模型进行真人设对话验收。不能把局部测量当成整个应用的资源降幅；模型对精简协议的遵循和个性化质量仍需实际使用观察。精简分析看不到长文本的中段，不会据此编造被省略的证据。
