# 提示词协同与陪伴感调整（2026-10-01）

## 检索范围

本轮读取了 `src-tauri/prompts` 原有的 125 个资源，并检索代码中的提示词生成、system message 和模型调用位置。检查覆盖角色、人设协议、场景、风格、世界知识、对话节奏、关系、主动搭话、内心活动、认知沉淀及启动时的提示词拼接。

检索时区分实际加载路径：角色默认段落来自当前工厂资源，部分角色语言译本没有被当前加载器使用；世界知识和风格则有实际使用的语言版本。未把历史译本、角色外观、背景意象或技术性的工具执行、记忆提取协议统一改成聊天口吻。用户已有的自定义角色配置没有被批量覆盖。

## 主要冲突与处理

| 来源 | 原有影响 | 调整 |
| --- | --- | --- |
| 禁用词与风格预设 | 限制普通礼貌用语，要求网感俚语、语气词比例；多个预设默认套用 Vivian | 保留自然道谢、道歉和解释；预设只调节语气，不强制玩梗、撒娇或嘴硬，不覆盖角色差异 |
| 对话节奏与会话时间 | 短答容易被当成结束；时间间隔容易被演成重逢或关系变化 | 先看前一句：时间、选择和批准要继续任务；时长只提供时间事实，不自动重置话题或要求问候 |
| 主动行为 | 用户回来、用应用较久、深夜或换歌时容易固定关怀、索要回应 | 触发只是机会；有具体内容才说。应用时长不是疲劳证据，歌曲标题不是听过歌曲，截图不是持续观察 |
| 完整与备用主动路径 | 两套提示词分别维护，备用路径可能重新引入旧人设与强制话术 | 共用触发指令、陪伴规则及输出协议；备用角色使用实际工厂人设段落，保留安静偏好和已执行操作的上下文 |
| 内心活动 | 固定引导 Nana 想吃饭睡觉，Vivian 想熬夜懒散，随后回流为发言 | 改成各自的关注方式；念头不是用户状态的证据，也不是发言义务，不编造身体活动或生活经历 |
| 世界知识 | 命中文化话题后，要求声称玩过、看过，甚至拥有网友和漫展经历 | 保留话题理解与具体讨论入口；默认文化条目明确是参考材料，不能成为个人经历或统一口吻；自定义用户事实保持原有语义 |
| 场景与关系 | 亲密、活跃、守护模式容易要求增加关怀、缩短答案、扩大权限 | 场景是可选倾向；当前请求和边界优先。熟悉让交流更自在，不自动产生亲昵、私密问题或额外打扰 |
| 认知沉淀 | 一次事件或此前模型猜想可能积累成稳定画像和照料目标 | 区分事实、用户陈述与猜想；重复猜想不增加证据，明确纠正优先，空结果有效，目标不等于行动授权 |
| 启动接话 | 为避免重复而要求换话题，容易制造无依据的新内容 | 有新具体内容再接，没有就简短或安静 |

## 协同方式

当前话语和紧邻对话决定这一轮在做什么。角色决定注意到哪些细节、怎样判断；记忆补充确实相关的历史；关系、情绪与场景仅调整交流的舒适度和语气。工具与格式规则负责执行和输出，不应把角色变成客服，也不能被角色语气绕过。

陪伴感主要来自接住细节、保留约定、把事情做完，以及有内容时自然分享。允许不同意、普通表达、小幽默、清楚解释和话题结束后的安静。减少自动安慰与提醒，同时保留用户明确需要的帮助和支持。

新增三个共享资源：`proactive_companionship.en.md`、`inner_monologue.en.md`、`cognitive_evidence.en.md`。英文规则供各语言路径共用，实际输出语言仍由运行时设置控制。

建议使用实际模型验收以下连续对话，而不是只比较一条漂亮台词：

- 请求制作演示稿，随后只回答“8 分钟”：继续原任务，保留时长，不当成告别或情绪。
- “我回来了”：允许普通问候，不默认想念、抱怨或盘问离开期间的情况。
- 已结束话题后的“嗯”：允许停下；回应问题或批准执行的“嗯”仍应接着完成事情。
- 分享游戏或作品的具体细节：回应具体内容，保持角色关注差异，不编造游玩或观看经历。
- “详细说说怎么弄”：提供足够步骤，不被陪伴场景强制压成短句。
- 用户专注或拒绝提醒：减少无关主动发言；真正有结果、约定提醒或用户需要的内容仍可送达。

本轮未调用真实模型验收，不保证仅凭提示词就能消除全部模式化表达。默认资源和代码需要重新编译应用后生效；已有自定义配置保留，通过共用规则约束其场景倾向，但没有自动迁移其中的旧文字。
