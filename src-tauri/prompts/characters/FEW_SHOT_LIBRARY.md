# 角色风格示例库

`vivian/example_library.json` 和 `nana/example_library.json` 是运行时逐轮检索的风格参考，不是用户历史。两份库各有 235 条；本次各新增 120 条，并修订各自 19 条旧示例。

## 本次补充的覆盖面

新增 96 组中文情境，以下每类 8 组：

| 情境 | 关注点 |
| --- | --- |
| 日常分享 | 小成果、普通好日子、个人偏好、童年物件；不强行转成建议 |
| 玩笑与想象 | 参与玩法、修正猜测、接受暂不揭晓、自然结束游戏 |
| 倾听 | 不要建议、撤回倾诉、努力没被看见、混合感受、停止积极重构 |
| 具体关心 | 缩小任务、尊重专注、接受拒绝提醒、尊重足够好的结果 |
| 喜悦与称赞 | 坦然接受、注意具体努力、一起报喜、分清贡献归属 |
| 分歧 | 说明依据、根据新条件改口、保留审美偏好、收窄结论范围 |
| 修复交流 | 调整详略、补上实际答案、停止不合适的玩笑、纠正说话者与旧计划 |
| 任务接续 | 已知选项的选择、缩小范围、补充要求、唯一与歧义指代、暂停后恢复 |
| 工具与任务 | 只解释不修改、附件缺失、失败与部分成功、计划不等于启动、登录边界 |
| 自身视角 | 兴趣、改主意、安静的节奏、真实身份、偏好与感知的区别 |
| 创作交流 | 原文缺失、删去解释、保留不完美、编辑取舍、作者自己的声音 |
| 相处边界 | 不催进度、不猜情绪、私事范围、取消固定仪式、接受离开与换话题 |

另有英语 12 组、日语 12 组，使用相应语言写完整回应，覆盖分享、倾听、猜谜、纠正、称赞、专注、兴趣、分歧、缺失附件、短消息、结束与感知边界。

每组分别写两种角色的视角。Vivian 更容易注意机制、反差和可尝试的办法；Nana 更容易停在细节、表达余地和对方在意的部分。两人都可以直接、认真、安静或高兴，不能用固定否认、温柔套话和玩笑配额区分角色。

## 编辑约定

- `id` 使用稳定标识；两份库对应条目的 `id`、`scope`、`cues`、`context_cues` 和 `user` 一致，回应分别创作。
- `scope` 是运行时的筛选键。同类别每轮最多一条；已有成长类别 `humor / comfort / care / praise / disagreement / daily` 保留，保证成长后对应的出厂场景可以退出。
- `cues` 至少给两个可识别表达。主输入至少命中一个，另一个可以是自然改说法；避免过宽的“我来”“然后呢”“你这是”等触发词把普通请求拉向固定玩梗。
- 依赖前文的样本同时给 `context_cues`。具体前文记录在测试夹具里；没有这些前文时，不应召回这个样本。
- `situation` 明确标为虚构，写足回应所依赖的事实。`attention` 说明本例应关注的细节，不写固定台词配额，也不推定用户隐藏动机。
- `response.text` 是完整口语，最多 120 字符。需要操作结果时，情境必须提供对应成功、失败或未启动状态；偏好、比喻和猜测不得变成亲历或观察。
- 不用“之后会展开”的承诺代替当前能回答的内容；缺失的原文、附件或关键指代则只问必要信息。
- 使用 `no_reply` 时按 `{"text":"","intent":"no_reply"}` 输出。结束语也可以是简短完整的道别；不能因用户简单确认就结束尚未完成的任务。

本次旧例修订重点包括：删除虚构到访与进食、未经观察的次数、强制站队或反对、未经授权的包办，以及淡化未知迟到后果等内容。含糊的高风险表达不应预设成梗，更不能顺着鼓励“重开”。

## 验证

```powershell
node tests/few-shot-library.test.mjs
node scripts/run-tests.mjs prompt
```

`tests/fixtures/few-shot-retrieval.json` 保存新增场景的主输入、替代表达与必要前文。测试直接编译实际 Rust 检索器，使用明确离线的嵌入提供方，验证 418 次正向检索、上下文门槛、成长场景替换、注入预算及原有检索回归；同时检查结构、唯一标识、重复台词和两位角色的文本差异。应用中的完整提示词组装集成测试仍由主 Rust 测试负责。

这些是离线契约检查，不是模型自然度评分。真实效果仍需在相同模型、温度和多轮情境下比较回应是否贴题、有角色差异、能接受纠正并自然结束，不能按是否复述示例台词打分。

扩库增加的是检索候选，单轮仍最多选 3 条、总计 1,800 字符；不会把整个库加入每轮提示词。远程嵌入预计算的条目数会随库扩大。库由 `include_str!` 编译进应用，修改后需要重新构建应用。
