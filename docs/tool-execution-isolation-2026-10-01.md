# 桌宠工具执行隔离

## 流程

主智能体保留角色、对话和记忆，决定是否调用工具及调用参数。实际执行由 `pipeline/tool_execution.rs` 管理，使用独立消息列表。

前台查询、截图和画面识别直接返回工具回执，不额外请求执行模型。其他多步任务可以调用中性执行模型，其输入仅包含原始任务、已解析的工具参数和实际执行结果，不包含主智能体人格、记忆或对话历史。执行模型的自然语言草稿被丢弃。

宿主程序从实际 `ToolCallResult` 构造回执，保留工具名、调用 ID、状态、成功标记、目标完成标记、时间、证据和错误。主智能体收到回执后判断是否需要继续查询，或以角色口吻回答。执行器停止调用不等于用户目标已经完成。

原生 function calling 和文本 JSON 工具调用共享此边界。适用渠道为 direct、proactive、wechat、cross_character；其他工作渠道保持现有流程。纯内部思考、询问用户和角色间交谈由主智能体决定，执行器不能自行发起这些交互。

## 隔离与约束

- 请求级 `without_framework_instructions()` 禁止 provider 自动向执行模型注入桌宠框架。开关通过 task-local 作用域传递，不修改共享 provider，其他角色并发请求与后续请求仍使用原框架。
- 保留原有工具权限、确认机制、动态工具加载、重复调用检测和轮次预算。执行器不能把工具内容当作新增授权。
- 工具产生回执后，主智能体表达失败不会触发整次工具执行重放，防止重复副作用。
- 画面识别只返回客观 `description`，不生成角色 `reply`；最终表达仍由主智能体负责。

## 验证范围

新增本地模拟模型服务的流程测试：主智能体发起调用 → 私有执行模型追加查询 → 返回真实回执 → 主智能体回复。检查执行请求不含角色和记忆、主智能体不收到执行器草稿、前端只收到主智能体最终文本。

另有请求隔离与并发恢复、失败回执和调用配对、文本调用解析、画面观察丢弃旧角色回复等测试。模拟流程验证消息边界，不保证真实模型每次都采用理想措辞；实际角色表现仍需在重新编译启动后用真实对话复核。

本次验证结果：`cargo check --lib` 通过；新增 4 个执行流程测试、请求隔离与画面证据各 1 个测试，以及相关对话循环、回复解析、工具管理、前台观察、重复调用检测测试，共 80 项通过。`git diff --check` 通过。未调用真实远程模型验证角色措辞。
